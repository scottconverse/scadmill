How it works

The code is the project. Everything else is a view of it.

ScadMill owns editing, project state, parameters, viewers and review flows. OpenSCAD stays the geometry authority and runs as a separate process, so the model you save is the model OpenSCAD evaluates.

  1. Ordinary .scad source

    Folder-backed, multi-file, with include and use resolved relative to the project.

  2. ScadMill workbench

    Editor, Customizer controls, projects, history and review surfaces.

  3. Immutable render request

    A snapshot of source and parameters is sent for rendering, so later edits cannot change a render in flight.

  4. Pinned OpenSCAD process

    An executable that does not match the recorded engine version is rejected for rendering.

  5. Validated geometry

    Color-preserving 3MF or sanitized SVG feeds the 2D and 3D viewers. Only full renders can be exported.

Failed, cancelled, stale or unavailable results are shown as such, and the last good geometry stays on screen.

Capabilities

A working environment, not a private format.

Everything below is part of the 0.1.0-beta.3 Windows desktop release. Rendering and export need the separately installed OpenSCAD snapshot.

01 / WRITE

Edit like a codebase

A purpose-built OpenSCAD grammar and a project-aware editor.

  • Syntax highlighting, completions, diagnostics, parse-gated formatting
  • Ignore-aware project search and replace
  • Outline, cross-file definition and reference navigation
  • Light, dark or high-contrast themes, configurable shortcuts
02 / ORGANIZE

Projects stay in folders

Desktop projects remain in folders you choose, not in a ScadMill store.

  • Tabs, binary assets, ZIP portability
  • Recovery of unsaved buffers after interruption
  • Inline or side-by-side resolution of changes on disk
  • History, libraries and a split editor
03 / RENDER

Preview fast, render for real

Press F5 for preview geometry or F6 for an unrestricted full render.

  • Animation of models that use $t through a bounded, cancellable loop
  • Opt-in per-project render cache, off by default
  • Geometry identity and volume, bounds and triangle-count changes between renders
04 / INSPECT

See what you built

A 3D viewer and a 2D SVG viewer.

  • Orbit, pan, zoom, fit, projections and axis views
  • Measure geometry, pin annotations, capture PNG screenshots
  • Section view and camera bookmarks
  • Printability checks and color or multi-part preview
05 / PARAMETERIZE

Customizer, unchanged

Stock OpenSCAD Customizer declarations become typed controls without silently rewriting your source.

  • Save, import and export named parameter sets in the stock JSON format
  • Batch export and a headless CLI that exports a named parameter set to 3MF
06 / EXPORT

Full-quality output

Export full results to 3MF (color-preserving), binary or ASCII STL, OFF, AMF, SVG, DXF and PNG, where the model supports the format.

  • Slicer handoff
  • Design-time manufacturing estimates using embedded Kiri:Moto 4.7.1 with generic profiles, labeled estimate-only

Quick start

From installer to a rendered cube.

The steps below follow the project README and the Windows beta guide. The engine download is a deliberate separate step: ScadMill does not bundle or modify OpenSCAD.

  1. Download the installer ScadMill_0.1.0-beta.3_x64-setup.exe from the official release.
  2. Verify it. The published SHA-256 is on the release notes, and Windows should report a valid signature from Scott Converse. The command is on the right.
  3. Get the engine. Download and verify the official OpenSCAD 2026.06.12 Windows snapshot using the engine instructions.
  4. Point ScadMill at it. Start the app, choose Configure engine, and select the verified openscad.exe.
  5. Render. Enter cube([20, 20, 20]);, press F5, and orbit the result.

The installer is current-user, includes uninstall support and an offline WebView2 runtime, and registers .scad files. Editing and project work are available before the engine is configured; rendering and export are not.

Privacy and control

Optional automation, with consent at each step.

ScadMill includes no telemetry and operates no cloud service or AI proxy. Network traffic happens only when you start it: a request to an AI provider you configured, or an engine or library download you ask for.

Provider-direct AI, if you want it

Configure an OpenAI-compatible, Anthropic or local provider. You choose exactly which source, diagnostics, parameters or viewer image enters a request, and proposed edits stay reviewable per hunk.

Secrets in Windows Credential Manager

AI credentials are scoped separately, stored in the operating system credential store and excluded from settings exports. The desktop broker refuses redirects.

A local MCP bridge, off by default

Connect a local MCP client through the desktop app. The bridge is loopback-only and permissioned; mutation tools are denied unless you grant a session permission, and accepted requests still enter the History review surface before changing a project.

Pinned execution

Rendering rejects an OpenSCAD executable that does not report the recorded engine version, so results come from the engine the release was verified against.

Architecture

Capabilities, not operating-system calls.

The shared application depends on typed capability ports. The desktop adapter supplies files, dialogs, keychain, menus and the native engine. Unavailable behavior is omitted rather than simulated.

INTERFACEReact workbench + CodeMirror
APPLICATIONServices + typed capability portsIndexing, mesh parsing and ZIP run in workers
DESKTOP ADAPTERTauriFiles, dialogs, keychain, menus, window state
OUT OF PROCESSUnmodified OpenSCAD subprocess
OPTIONAL, EXPLICIT CONTEXT ONLYYour configured AI provider
  • Local state. Source, projects, settings and recovery data stay on the machine unless you invoke a configured provider.
  • Browser path exists, is not shipped. A browser-source adapter and a verified OpenSCAD WASM worker are implemented for development and verification, but no public browser app or WASM package is offered.
  • Documented failure model. The architecture guide covers render lifecycle, data ownership, worker boundaries, packaging and supply-chain controls.

What the release evidence does and does not cover. The tag, signed installer source and commit 179ef30 are identical; all nine required hosted checks and the isolated similarity gate passed on that source. The final exact-main clean-environment rerun was not completed, and the owner accepted publication without it. Do not treat beta.3 as fully release-proven.

The Radeon 780M was the performance-evidence host. It is not a minimum GPU requirement. Uninstalling does not erase every desktop store; the Windows beta guide lists what to clear first.
